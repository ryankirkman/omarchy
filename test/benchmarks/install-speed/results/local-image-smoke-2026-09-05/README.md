# Local image installation smoke

`failed-01` is a failed functional test, excluded from performance comparisons. The candidate booted through the original firmware/GRUB path, completed all nine upstream image-installer phases, and booted the installed Btrfs root. Its 941 package versions and 158 explicit-package reasons matched the stock calibration exactly. Package-file validation then correctly failed because `/var/log/cups/` and `/var/log/old/` were missing. The standalone reboot gate did not run, and the supervisor exited with status 1.

The validated source image contained both directories with their package-owned metadata. The pinned upstream restore code created a fresh `@log` subvolume and copied only `pacman.log` into it, then mounted it over the image's remaining log directories. The correction initializes every image-backed Btrfs child mount from its source subtree before replaying mounts; it does not recreate individual paths after installation.

`failure-evidence.json` identifies the failure and hashes the preserved evidence. The source ISO, root image, supplemental media, initramfs, launch arguments and recovered-build provenance are recorded separately. No private SSH keys, credentials, VM disks or mutable firmware files are included. After publication at `d931066f6e9e79983acf49bdf3dcc9cd219e721e`, only the stopped failed target was reclaimed; `failed-target-cleanup.json` records its checksum and the cleanup. A new target must pass all validation and reboot gates before this correction can be called successful.

`corrected-media-02` records the supplemental ISO revision for that fresh test. All ten ISO members were checked: only the installer-overlay archive and its two metadata files changed. The sealed root image remains byte-identical, with SHA-256 `6ef64246e8b7d01e8f129046bae0d8e41228f7f195fd4c1ffb8fe00e4d00ca3e`. The corrected supplemental ISO has SHA-256 `19de1071bc7825078324c21243b4371f5bb6f4d9f47608b16c11288d22919e97`. Its root-image byte offset changed from 67584 to 116736; both source-range metadata versions are preserved. This is media verification, not an accepted installation or speedup result.

`passed-02` is the fresh functional rerun with that corrected media. All nine phases succeeded, all 941 package versions and 158 explicit-package reasons matched the stock calibration, and `pacman -Qk` returned zero. CUPS reported 946 files with none missing; filesystem reported 127 with none missing. The installed root booted through firmware, then passed a second ordinary reboot in the same QEMU process after both installation CDs were ejected and CIDATA was unplugged. The second boot ID changed while the installed root and its identities stayed the same. The machine ID, filesystem UUID, pacman master key and SSH host keys differ from both stock calibration and the earlier failed candidate. QEMU and its supervisor subsequently exited cleanly with status zero.

The first installed SSH was observed at 739.734 seconds; the guest installer took 431.572 seconds. These are unpaired TCG functional measurements, **not a speedup result**. `seal.json` hashes the original timing, first-boot profiles, package inventories and independent reboot proof. The comparator accepted this evidence before sealing; first-boot profiles were not replaced by second-boot output. `functional-result-02.json` records the acceptance scope.

`source-inspection-02` records an additional untimed, read-only source inspection performed after both installation gates. The source device and sealed subvolume were read-only, and their filesystem UUID differed from the installed root. The source had no random seed or machine-info file, an empty regular machine-id, and a dbus machine-id symlink to that empty ID resolved within the source namespace. No identity-file content bytes were read. The inspection returned no concerns, and independent checks proved the source was unmounted before the USB device and block backend were removed. The original source bytes remained unchanged.
