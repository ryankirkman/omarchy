# Private logging helper experiment

This opt-in layer uses the fork's Bash built-in timestamp logger during serial system setup while preserving the original package-owned helper on disk. The firewall, user and late index invocations keep their original logging path. It composes after the exact full-overlap payload, or after the explicitly pinned firewall-overlap payload. It does not change the default installer, installed package database, supplemental root image, package file counts, or the localdb overlap source checks.

`prepare-payload.py --iso-source CHECKOUT --base-payload PAYLOAD --base-preflight PREFLIGHT --output FRESH_DIRECTORY` verifies the base manifest's complete file inventory, bytes and modes, the pinned upstream source, the original phases and inherited preflight, and the optimized repository logger. It preserves inherited files, adds the staged helper and guard, retains both source licenses, and writes a complete manifest. `preflight.sh` verifies the staging inventory before activating the inherited layer exactly once and replacing only the verified live orchestrator phases.

The upstream source is `dbffaa6c65344d644627a023c28661e08382b8fa`. The package logger is pinned to `61a13abcc44fd5241e9882f1bcfed833e10e0ed19ad42c34a08efe1973b70d27`; the optimized helper is pinned to `1d8151adb150bc1dfe930b30e7039978591add500a132b9951152d7a8a23d715`. The two exact supported phase hashes and variant names are listed in `patch.py`; preparation and activation both enforce the matching inherited preflight hash.

The generated target setup function has an explicit `logging_bind=False` keyword. Only the unique serial `run_system_finalizer` call opts in with `True`; the other setup calls retain the original subprocess invocation. The manifest and activation file both identify `logging_scope: serial-system-finalizer-only`. The orchestrator loads the verified guard module once, then calls its `run` function directly within the existing target setup `try/finally`. The guarded call retains the original private `unshare` and `arch-chroot` command and adds an inner Python process. An inherited namespace descriptor proves that the child entered a different mount namespace. The child bind-mounts the staged helper onto the original helper path, remounts it read-only, checks the mount options and exact staged inode, and executes the unchanged command. It unmounts the helper and verifies the original file metadata afterward. The parent independently checks its mount table and original file metadata, including device, inode, permissions, owner, size and modification/change times. Missing namespace support, stacked mounts, source drift, child failure or unsuccessful cleanup cannot report success. The existing unified-log cleanup still runs when the guard or child fails.

The single guarded setup call adds one inner Python startup, five `findmnt` calls and three bind/remount/unmount calls: nine subprocess launches beyond the retained `unshare` and `arch-chroot`. In the firewall composition it removes 100 external `date` launches from the 49-leaf serial system branch and its final duration record. The [logger source audit](../../results/install-logging-iso-audit.md) measures about 0.505 seconds saved for 80 trivial leaves on the host. Scaling that component result to these 100 calls suggests roughly 0.32 seconds before guard costs; it is not a measured installation improvement. Native full-clock comparisons remain the acceptance criterion.

Run `python3 test/benchmarks/install-speed/logging-bind/contract-test.py --iso-source CHECKOUT` for the focused host contracts. They cover exact source pins and staged inventories, root/user command preservation, namespace refusal, read-only verification, child/error cleanup, generated guard loading and caching, status propagation, the explicit system-only opt-in and default original path, and execution of the actual generated setup function's original log-cleanup path. Mount operations are simulated in these host contracts; they do not establish kernel mount behavior.

`guest-contract.py --guard GUARD --original-helper ORIGINAL --optimized-helper OPTIMIZED --output FRESH_JSON` performs the bounded kernel behavior check in an owned disposable guest. It copies only Bash, `date` and their shared libraries into a temporary target, then exercises root success, user success and child exit 37 through actual private `arch-chroot` calls. A failing external-date sentinel proves that the optimized logger handles timestamps internally. A paused child lets the parent inspect the original file and absence of a parent mount while the replacement is active. Read-only writes must fail; package inode/hash/metadata and mount cleanup are checked after every case.

The guest script also defaults to three alternating component timing pairs with `--logging-scope serial-system-finalizer-only`. Each sample runs the same four serial command groups with 49, 1, 12 and 1 trivial leaves. The baseline uses the original private chroot throughout; the candidate calls the actual imported guard `run` path for the first group and retains three original chroots. It observes the loaded helper body in every invocation and verifies the original package file and parent mount afterward. Raw invocation and sample times retain guard checks, mount operations and inner interpreter startup costs. The controller imports the guard module before the component stopwatch; its one-time verified module load is included in the native installation clock. This serial fixture does not reproduce the real install's parallel branch schedule. Its TCG timing is a component regression screen, not a native performance result or a completed-install proof. `--timing-pairs 0` runs only the functional contract; the explicit `all-target-setup-commands` scope preserves the rejected earlier experiment as a distinct mode. The fixture never installs a target system, configures the host firewall, or launches an additional VM itself.

The [fresh system-only guest result](system-only-guest-result.json) passed all functional cases and all three alternating timing pairs: 15.617235→12.076732, 15.316387→12.665245 and 14.317359→11.764141 seconds. Recomputed medians are 15.316387→12.076732 seconds, a 3.239655-second reduction and 1.268256× component speedup. Every candidate sample observed the optimized logger only for its 49-leaf call and the original logger for the remaining 1/12/1 leaves. All leaves, original package metadata, parent mount isolation and fixture cleanup passed. The [evidence manifest](system-only-guest-evidence.json) pins the exact result and component source bytes. This clears the component regression screen; a full native trial must establish the installation effect.

The earlier all-call guest check on 2026-09-06 passed root and user setup, exact child exit 37, read-only replacement, concurrent parent isolation, original package inode/metadata preservation and fixture cleanup. Its [three alternating timing pairs](rejected-all-call/logging-guest-result.json) failed the component regression screen: baseline median 14.641953 seconds versus candidate 15.879115 seconds, a 1.237162-second increase (0.922089×). Every paired total was slower with the guard. The 49-leaf invocation improved, but repeated guard costs on the shorter invocations exceeded the aggregate timestamp savings. That all-call logging layer is a rejected performance experiment, preserved in commit `6a92e6a` with its [producer manifest](rejected-all-call/payload.manifest.json) and source hashes. The guest was booted with a diagnostic Plymouth-disable setting solely to exercise these bounded contracts; that setting is not part of any measured installer candidate. Fresh system-only samples must not be mixed with this earlier result.

Two earlier guest fixture attempts are retained with the successful result: the original script lost child output before its handshake, and the diagnostic rerun revealed that `arch-chroot`'s private `/tmp` mount hid the test leaf and FIFO. The final fixture places those inputs under `/opt/logging-bind-contract` inside its temporary root. The guard, staged logger and production phases were unchanged throughout these fixture corrections.
