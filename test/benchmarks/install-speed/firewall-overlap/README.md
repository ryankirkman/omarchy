# Required firewall setup in the joined user branch

This opt-in component follows the complete direct-restore, localdb and foreground-animation payload. It moves the unchanged `run_logged "$OMARCHY_INSTALL/config/firewall.sh"` leaf from serial system setup to the first step of the existing user branch. The boot and user branches still join before boot validation and the factory snapshot. Firewall setup remains before user provisioning, SSH/Tailscale rule additions and the unchanged locate index. Deferred provisioning retains the original serial command and performs no late firewall work.

The target package files are never edited. The existing localdb shell transformation is extended by expanding the exact `config/all.sh` source call without its firewall leaf. The generated shell retains the original `$0`, arguments, options, logging helper and other setup calls. The late leaf uses the existing root `_run_target_setup_command` helper, including its private chroot and unified log lifecycle. Its original install flags and runtime-bin PATH prefix are restored explicitly. A pending-state guard requires successful firewall execution exactly once; command failures retain original `Failed` records and stop the user branch. Boot work joins before the failure is raised.

The firewall leaf retains both default policies, LocalSend UDP/TCP rules, both Docker DNS rules, the temporary UFW status shim used by ufw-docker, `ENABLED=yes`, and enable-only UFW service setup. Its write set is `/etc/default/ufw`, UFW user/after rules, timestamped ufw-docker backup files, `ufw.conf`, temporary files and the enabled service symlink. SSH and Tailscale later write the same user-rules file, so firewall setup is placed before them. All these required writes finish before indexing. Backup filenames can have later timestamps; this is not a claim of byte-identical locate databases or timestamped backup paths.

The pinned settings hook (`omarchy_hooks.conf`, SHA256 `7cdb671b0c49bcd5627bdf24db9fee3417b065cd984d96068ed2b0a929e3b6bc`) selects udev/Plymouth rather than a systemd initramfs. The base `FILES=()` and selected hooks do not collect UFW configuration or enabled-service directories. The selected mkinitcpio hooks, including the exact Plymouth and btrfs-overlayfs hooks, were inspected from MTREE-verified package bytes. The firewall leaf invokes no package manager or initramfs builder. The private chroot isolates mounts; it is not a network namespace, so the existing config-only UFW behavior and its status shim must remain intact.

In native run 34005907730 the measured boot-minus-user branch slack was 1.23268, 0.58513 and 0.47770 seconds. If the removed serial firewall cost is F and its additional late wrapper cost is H, with other work unchanged the possible saving is `min(F, boot - user - H)`. Contention and traversal timing can change those terms. There is no precise retained firewall-leaf timing from that run, so this component makes no measured install-speed claim. Moving it can extend indexing beyond the former boot endpoint; that does not skip indexing, and the branch slack bounds the useful overlap.
